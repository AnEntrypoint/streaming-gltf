gm GRAPHICS-PIPELINE LESSON (generalizable): when a custom format packs index/vertex ranges with an offset table the runtime depends on, do NOT run a 'optimize' transform that reorders buffers (e.g. gltf-transform meshopt() runs reorder()+quantize() = re-permutes vertices/indices for GPU cache) AFTER building the table - it silently scrambles every offset. Apply compression at WRITE time in a layout-preserving mode instead (EXT_meshopt_compression via setEncoderOptions({method:FILTER}) = lossless filter, no reorder). Witness the offset invariant after compression (sum of LOD0 ranges == primitive.indices count), not before. Also: a custom-extras-referenced accessor is invisible to the graph, so prune() garbage-collects it - keep its object ref and resolve its final index post-transform, or skip prune.
