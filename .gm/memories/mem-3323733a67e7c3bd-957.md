gm DEBUG LESSON (generalizable): when a newly-added editor/tool plugin 'doesn't appear' in an app-plugin runtime, the bug is usually NOT the plugin code but the LOAD LIST. Plugin runtimes often load only apps referenced by the current world/scene/document (entities' app field + placeable/trusted lists), not every app on disk. An editor-global tool tied to no entity is silently excluded. Debug path: expose the client's loaded-module registry as a window.* global, read it live (was [world-app] only, tool absent) -> the tool never arrived, so the panel-mount never ran. FIX: add the tool to an always-load editor-apps allowlist at the load-list assembly point, not per-world config. Also: a running dev server predates newly-created app files unless restarted (dir-scan happens at boot); but a per-page worker that fetches app source fresh picks up new files on reload without a restart - check which load path applies before assuming 'restart fixes it'.
