gm OPS LESSON (generalizable): serving a large binary corpus (~1GB of GLBs/textures) over GitHub Pages from a git repo. (1) Pushing ~1GB of NEW blobs to github.com reliably fails with 'send-pack: unexpected disconnect while reading sideband packet' - exceeds push size/time. FIX when the same bytes already exist on another origin branch: reset the target branch to that branch (reuse pushed blobs) and re-apply only the small non-blob delta (deletes + manifests + workflow), so the push transfers KB not GB. Byte-churn (e.g. re-baked binaries) is what makes a push huge even when 'nothing structural changed' - avoid re-committing regenerated binaries if a functionally-equivalent version is already pushed. (2) A Pages workflow that globs source files must be retargeted when the repo goes derived-only. (3) GitHub Pages serves Access-Control-Allow-Origin:* so a code-only demo/editor can fetch a manifest + stream the binaries cross-origin with zero server. (4) First Pages deploy that thumbnails ~1000 assets in CI is slow (10-20min) - it is CI-time, not a blocker to resolve inline; verify the live manifest/asset 200s after it finishes.
