## Resolved mutable: per-switch-cost-dominant-op

Instrumented _applyLod at steady state (browser-712/714, 500 models, orbit/zoom off, target60). RESIDENT-geometry switch is NEAR-FREE: frames WITH a LOD switch averaged 7.8ms vs 7.2ms without (only +0.6ms), switchFrameMax 12.8ms — no spike (browser-714: 80 switches/108 frames smooth dolly, maxMs 30.2 was a NON-switch frame). The new-Mesh/SkinnedMesh alloc branch NEVER fires (assets unskinned -> always geomOnly path, browser-710 newMesh n:0). Material program swap negligible (programsCompiled:1 total). The big 335ms avg in browser-710 was MID-LOAD streaming contention (assets still decoding), not the swap. So the residual 'cost' = (a) cacheMiss switches during streaming (~8.8ms, max 33ms) i.e. geometry not yet resident, and (b) first-use GPU buffer upload when tm.mesh.geometry=geo (a render-time GPU stall not captured in JS _applyLod timing). DOMINANT op = geometry residency/upload on first switch, NOT the JS swap. Fix direction: preload+pre-upload all LOD geometries for resident entities so every switch hits a warm cached+uploaded buffer.
