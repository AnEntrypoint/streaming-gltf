streaming-gltf per-switch LOD cost ELIMINATED (commit 3b7dab1, pushed master). The 'cost to switching' at 500-1000 was NOT the JS Mesh/material swap (measured ~free for resident geo, +0.6ms/frame browser-714) — it was CACHE MISSES: LODs load lazily on first pick, so at 1000 a dolly hit 11,310 switches / 11,242 misses (only 1725/5868 LOD geos decoded), each awaiting fetch+decode+GPU-upload ON the switch frame -> p50 66ms. FIX (user spec: lazy from network, EAGER to GPU, piecemeal with headroom): (1) _applyLod cache-miss no longer awaits — registers want via pool._enqueueLodWarm + sets tm._lodWantIdx; picker skips re-invoking _applyLod for an already-requested unresident target (kills the 11k re-fire). (2) _drainLodWarm in update(): adaptive per-frame budget (2x starts above target+5fps, 1x near, MIN 1 below — NEVER 0 or it deadlocks), nearest-first, decode off-thread then _gpuWarmGeometry (render geo once into a 1x1 offscreen WebGLRenderTarget to force buffer upload) so the switch has no first-use GPU stall. (3) CRITICAL exception: when dropping to a CHEAPER LOD (wantIdx<currentLod, recovers FPS) OR no renderable geo, AWAIT now — else entities strand at expensive LOD = a fps:1 all-lod2 DEADLOCK (hit during iteration: warm loader gated off at low fps + miss-return-without-apply froze everything at lod2). Witnessed browser-744 (1000, extreme near<->far churn): switches 11310->271, misses 11242->3, maxSwitchesPerFrame 130->8, p50 6.2ms, fps 124-154, glErr 0; only an abrupt teleport-cut shows one ~75ms frame (was 161). LESSON: a background loader gated on FPS headroom MUST keep minimum forward progress (>=1/frame) or it deadlocks when the scene needs cheaper LODs to recover FPS; and don't let a deferred/queued switch strand an entity at a costly LOD. _gpuWarmGeometry pattern: reusable 1x1 WebGLRenderTarget + dummy scene/cam/mesh, set geo, render to target, restore prevTarget, mark geo.__gpuWarmed.
